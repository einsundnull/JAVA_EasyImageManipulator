2. MOCKUP A — ZIEHGRIFFE AM BILDRAND (Canvas)
------------------------------------------------------------------------------
Drei Griffe wie in MS Paint: rechts, unten, Ecke rechts-unten. Sie haengen
am BILD, nicht an einem Layer — deshalb liegen sie ausserhalb der acht
Element-Griffe und werden NACH ihnen getroffen (Trefferreihenfolge §22:
Handle -> Punkt/Layer -> Kante/Flaeche -> ZULETZT Bildrand).

   Canvas (grau) mit Bild:
   +------------------------------------------------+
   |                                                 |
   |   +==========================+                  |
   |   |                          |                  |
   |   |        B I L D           |                  |
   |   |                          [o] <- rechts      |
   |   |                          |    (E_RESIZE)    |
   |   |                          |                  |
   |   +=========[o]==========[/] |                  |
   |             ^            ^                      |
   |         unten        Ecke rechts-unten          |
   |       (N_RESIZE)      (SE_RESIZE)               |
   |                                                 |
   |   waehrend des Zugs:                            |
   |   +==========================+- - - - - -+      |
   |   |                          |           :      |
   |   |        B I L D           |  gestrichelte    |
   |   |                          |  Vorschau +      |
   |   +--------------------------+  Masszahl:       |
   |                                 :1200 x 800:    |
   |                                 + - - - - -+    |
   +------------------------------------------------+

  REGELN DES ZUGS
   - Griffe sind IMMER 8 px gross, unabhaengig vom Zoom (sie sind
     Bedienelemente, kein Bildinhalt) — gezeichnet in Screen-Space.
   - Die ZAHL im Etikett ist Image-Space (echte Pixel), nicht Screen-Space.
     *** Umrechnung ausschliesslich ueber screenToImage() / toSx (§27).
         Kein "* zoom" im Zughandler. ***
   - Verkleinern beschneidet (Inhalt weg), Vergroessern fuellt transparent.
   - Umschalt beim Eckgriff = Seitenverhaeltnis halten.
   - EIN pushUndo() beim LOSLASSEN, nicht pro Mausbewegung (§29:
     ein pushUndo pro Benutzeraktion). Vorbild: das aufgeschobene
     "pendingUndo" in CanvasPanel.
   - Minimum 1 x 1 px, Maximum wird gedeckelt (Vorschlag 20000 px je Kante)
     — sonst erzeugt ein unglueckliches Ziehen bei kleinem Zoom eine
     Leinwand, die den Heap sprengt. *** B01 hat gezeigt, was ein
     unbedachtes Bild im Speicher kostet. ***

5. MOCKUP C — VORLAGEN
------------------------------------------------------------------------------
Eine Vorlage ist: Format + Ausrichtung + vier Raender + (optional) Kopf-/
Fusszeile/Seitenzahl. *** Also exakt das, was PageLayout schon traegt und
PageLayoutManifest schon liest und schreibt (§6). ***

  Knopf in der oberen Leiste, neben "Neu":

  +-- Vorlage waehlen -------------------------------------+
  |                                                        |
  |  EIGENE VORLAGEN                                       |
  |   > Arbeitsblatt A4          A4 hoch  · 25/25/25/25 mm |
  |   > Postkarte Gruss          Postk.  quer · 5 mm       |
  |                                                        |
  |  MITGELIEFERT                                          |
  |   > A4 mit Rand              A4 hoch  · 25 mm rundum   |
  |   > A4 ohne Rand             A4 hoch  · 0 mm           |
  |   > A5 mit Rand              A5 hoch  · 20 mm rundum   |
  |   > Postkarte                A6 quer  · 5 mm           |
  |   > Letter mit Rand          Letter   · 25 mm rundum   |
  |                                                        |
  |  +------------------+   Format:  [ A4            v ]   |
  |  |                  |   [Hoch] [Quer]                  |
  |  |  Vorschau mit    |   Oben  [25] Unten [25]          |
  |  |  gestrichelten   |   Links [25] Rechts[25]  [mm v]  |
  |  |  Randlinien      |                                  |
  |  |  + 4 Ziehgriffen |   [ Als Vorlage speichern ... ]  |
  |  +------------------+   [ Vorlage loeschen ]           |
  |                                                        |
  |                          [ Erstellen ]  [ Abbrechen ]  |
  +--------------------------------------------------------+

  *** DIE VORSCHAU WIRD NICHT NEU GEBAUT. *** NewImageDialog hat sie
  bereits: MarginPreviewPanel (NewImageDialog:379-514) mit weisser Seite,
  gestrichelten blauen Randlinien, vier runden Ziehgriffen und
  Millimeter-Beschriftung. Der Vorlagen-Dialog ist derselbe Dialog mit
  einer Liste davor — *** kein zweites Vorschau-Panel. ***

  ABLAGE (Univ. §12 / §31: alle Pfade ueber AppPaths):
      %APPDATA%\TransparencyTool\templates\<Name>.layout
    Format = das des PageLayoutManifest ("key: value", UTF-8), erweitert um
    zwei Schluessel:
        name:        Arbeitsblatt A4
        widthPx:     794          <- damit "Benutzerdefiniert" moeglich ist
        heightPx:    1123
    *** Fehlender Schluessel = Default (Univ. §6). Eine .layout-Datei
        neben einer Buchseite und eine Vorlage sind damit dasselbe Format
        — sie unterscheiden sich nur durch den Ort. Kein zweites Format,
        kein sechster JSON-Serializer (§31). ***
    Die mitgelieferten Vorlagen stehen IM CODE, nicht als Dateien:
    ein fehlendes templates/-Verzeichnis muss genau das alte Startverhalten
    ergeben, und mitgelieferte Dateien, die der User loescht, kaemen beim
    naechsten Start wieder.

  RAENDER SIND OVERLAY, NICHT PIXEL (Befund 3, Frage F3):
    Heute brennt NewFileController:70-79 die gestrichelte Linie in das PNG.
    Vorschlag: stattdessen den vorhandenen, nicht-destruktiven Overlay aus

6. FUENF FRAGEN AN DEN USER  (F1 und F2 sind blockierend)
------------------------------------------------------------------------------
F1 *** WAS SOLL DAS ZIEHEN TUN? ***
     (a) LEINWAND aendern — Inhalt bleibt gleich gross, Flaeche waechst
         transparent oder beschneidet.  *** So macht es MS Paint. ***
     (b) SKALIEREN — Inhalt waechst mit (das, was der Dialog "Skalieren"
         heute schon per Eingabe kann).
     (c) BEIDES: ziehen = Leinwand, Umschalt+ziehen = skalieren.
     -> EMPFEHLUNG (a). Begruendung: (b) gibt es bereits als Eingabe, und
        der Prompt nennt MS Paint namentlich. (c) ist verlockend, aber
        Umschalt ist am Eckgriff schon fuer "Seitenverhaeltnis halten"
        vorgesehen — zwei Bedeutungen auf einer Taste ist genau der
        Konflikt, den §25 fuehren muesste.

F2 *** 25 px ODER 25 mm RAND? ***
     25 mm = 94 px · 25 px = 6,6 mm (bei den projektweiten 96 dpi).
     Das Projekt fuehrt Raender ueberall in mm; PaperFormat hat bereits
     25/25/25/25 mm als Vorgabe.
     -> EMPFEHLUNG: mm. Falls px gemeint war, wird die Vorlage "A4 mit
        Rand" einen Streifen von 6,6 mm zeigen — auf Papier fast nichts.

F3 *** RAENDER ALS OVERLAY ODER WEITER EINGEBRANNT? ***
     (a) Overlay (nicht-destruktiv, aus-/einblendbar, aenderbar, nicht im
         Export) — dafuer gibt es den fertigen Code schon.
     (b) wie bisher in die Pixel gebrannt.
     (c) Overlay, und zusaetzlich ein Knopf "Raender einbrennen".
     -> EMPFEHLUNG (a). (b) ist der Ist-Zustand und der Grund, warum
        Raender heute nicht korrigierbar sind.

F4 *** SOLLEN DIE ACHT "_DOC"-VARIANTEN AUS DER FORMATLISTE VERSCHWINDEN? ***
     Sie sind keine Papierformate, sondern Rand-Vorgaben (A4_DOC = A4 mit
     22/28/28/20 mm). Mit den neuen Formaten haette die Liste sonst ueber
     25 Eintraege.
     -> EMPFEHLUNG: ja — sie werden zu mitgelieferten VORLAGEN. Der Wert
        geht nicht verloren, er wandert nur dorthin, wo er hingehoert.

F5 *** WO SOLL DER VORLAGEN-KNOPF SITZEN, UND BRAUCHT ER EINE TASTE? ***
     Vorschlag: obere Leiste neben "Neu". Taste: keine — F1-F7 sind voll
     vergeben, und §25 verlangt zuerst den Registry-Eintrag.
     Falls doch eine Taste gewuenscht ist: Strg+Umschalt+N waere frei
     (zu pruefen), *** und sie kaeme ZUERST in KeyBindings, dann in den
     Handler. ***

ZWECK
--------------------------------------------------------------------------
Ein Dialog, der beantwortet: "Welche Taste macht was?", "Was kann die Maus?"
und "Wie mache ich X?" — gespeist AUSSCHLIESSLICH aus einer Registry.
Der Dialog enthaelt KEINEN eigenen Text (§25). Wer eine Funktion ergaenzt
und den Registry-Eintrag vergisst, dessen Funktion ist im Editor nicht
auffindbar.

OEFFNEN MIT:  SHIFT + F1
*** NICHT F1 — F1 ist mit "Zweitfenster ein/aus" belegt, F1-F7 sind
    vollstaendig vergeben. Bewusste Abweichung von GameLoop2 §11. ***

DATENMODELL (die Registry)
--------------------------------------------------------------------------
    enum Scope { GLOBAL, WINDOW, CANVAS, DIALOG, MOUSE }

    record KeyBinding(Scope scope, String combo, String description,
                      String condition) { }

    final class KeyBindings {
        static final List<KeyBinding> ALL   = List.of( ... );
        static final List<GuideEntry> GUIDE = List.of( ... );
    }

REGELN:
  - Neue Taste/Geste -> ZUERST Eintrag in ALL, DANN Handler-Code.
  - KeyboardShortcutManager VERDRAHTET die Registry; die Beschreibung
    steht nicht mehr nur im Code.
  - Mehrfachbelegungen werden mit Vermerk gefuehrt, nicht verschwiegen.
  - condition darf leer sein.


WAS DIE BESTANDSAUFNAHME ERGEBEN HAT (Anlass fuer den ganzen Schritt)
--------------------------------------------------------------------------
Quelle war der CODE (KeyboardShortcutManager + CanvasPanel), nicht die
vorhandene Tabelle. Ergebnis:

  doc/Shortcut Table.txt kennt 13 Eintraege.
  Tatsaechlich belegt sind ueber 40.

  ES FEHLEN DORT VOLLSTAENDIG:
    F1-F7, ALT+T, ALT+P, R, UMSCH+R, UMSCH+V, STRG+ALT+S, STRG+UMSCH+S,
    STRG+ALT+UMSCH+S, UMSCH+ALT+A, +/=/NUM+
  UND SAEMTLICHE MAUS-GESTEN, darunter zwei, die NIRGENDWO dokumentiert
  sind und die man nicht erraet:
    *** STRG + Rad auf einem Text-Layer aendert die SCHRIFTGROESSE
        statt zu zoomen ***
    *** ALT + T festhalten + Rad aendert die DECKKRAFT des Bild-Layers ***

Genau deshalb wird die Tabelle nach der Umsetzung aus der Registry erzeugt
oder geloescht (§25) — eine zweite, handgepflegte Liste ist die Ursache
des Problems, nicht die Loesung.
